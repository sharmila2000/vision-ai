Phase 2: Video Item Tracking — Model Analysis

Deep evaluation of models suitable for natural language queries over video, temporal localisation, and action/event detection

1. What Phase 2 Must Do

Input: A video file + a natural language question
Example query: "Where is the key?" or "Who moved the key?"
Expected output: "At 11:03 min, the person took the key and put it in their pocket."

Core capabilities required:
  • Process long video (minutes, not seconds)
  • Detect and track a specific object across frames
  • Identify actions involving that object (pick up, place, put in pocket)
  • Produce a timestamp-anchored natural language answer
  • Relate person + object + action + time in a single response

This is fundamentally a Video Question Answering (VideoQA) + temporal grounding task — very different from Phase 1's static image detection.

2. Solution Architecture Approaches

Approach A — Video LMM (Large Multimodal Model)

A single end-to-end model that accepts video frames and text, reasons across time, and produces a natural language answer with timestamps.

Video (.mp4)
→
Frame Sampler
→
Video LMM
→
"At 11:03, person put key in pocket"

Approach B — Detection + Tracking + LLM Pipeline

Specialised models chained together: a tracker finds the object, an action recogniser labels the event, an LLM narrates the result.

Video
→
OWLv2 / Florence-2 (detect)
→
SORT / ByteTrack (track)
→
Action Head
→
LLM Narrator

Approach C — Hybrid (Phase 1 backbone + Video LMM)

Use the Phase 1 hybrid model for frame-level grounding, add a video-temporal LMM for reasoning and narrative generation.

3. Candidate Models — Detailed Analysis

Qwen2.5-VL-7B / 72B — Video Mode
Alibaba / Qwen Team · 2025
7B (local) / 72B (API)
Video QA Temporal Already in Phase 1

Qwen2.5-VL already powers Phase 1 for image queries. Its video mode accepts an MP4 or a list of frames and natively supports timestamp-anchored grounding with <|video_start|> tokens. It can answer "At what time does X happen?" directly without post-processing.

✔ Strengths

  • Zero new dependencies — already installed
  • Native video input via qwen_vl_utils.process_vision_info
  • Temporal grounding: outputs second-level timestamps
  • Understands "who put the key in the pocket" type queries
  • Dynamic frame sampling (1 fps → 2 fps configurable)
  • MPS/CUDA/CPU compatible (same as Phase 1)
  • 7B fits in 16 GB unified RAM at float16

✗ Limitations

  • Max ~8–16 min video at 1 fps before memory pressure
  • 7B may hallucinate exact timestamps — needs 72B for high accuracy
  • No dedicated object tracker — frame-level only
  • Needs frame-chunking strategy for very long videos
Video-LLaVA
PKU-YuanGroup · 2023
7B
Video QA Older

One of the first unified image+video LMMs. Encodes video as 8 uniformly sampled frames processed with a CLIP visual encoder. Good for short clips, poor for long videos or precise timestamps.

✔ Strengths

  • Straightforward HuggingFace integration
  • Handles basic "what happens in the video" queries
  • Lightweight (7B)

✗ Limitations

  • Only 8 frames max — very coarse temporal coverage
  • No timestamp output
  • Cannot localise "at 11:03 min" level events
  • Significantly outperformed by Qwen2.5-VL on benchmarks
  • Not actively maintained since 2023
InternVL2.5 / InternVideo2
Shanghai AI Lab · 2024
8B / 26B / 76B
Video QA Strong Benchmarks

InternVL2.5 is a strong image+video LMM. InternVideo2 is a dedicated video understanding model. Both achieve state-of-the-art on MVBench and Video-MME benchmarks. InternVL2.5-8B can process up to ~500 frames via dynamic resolution.

✔ Strengths

  • Top-tier on Video-MME (long-form video benchmark)
  • InternVideo2 specifically designed for action recognition
  • Dynamic frame resolution support
  • Beats Qwen2.5-VL-7B on some video benchmarks

✗ Limitations

  • New codebase — new integration work required
  • InternVL requires separate lmdeploy or transformers setup
  • Timestamp grounding less natural than Qwen's implementation
  • 76B model needed for best results (API-only practical)
Gemini 2.0 Flash / Pro (Video)
Google DeepMind · 2024-2025
API-only
Best Video QA API Required 1M token context

Gemini 2.0 Pro accepts up to 1 hour of video natively. It can directly answer "where is the key at 11:03?" with timestamp awareness and understands complex multi-person scenes. Best-in-class for long-form video reasoning.

✔ Strengths

  • 1M token context window — entire 1-hour video in one pass
  • Native timestamp understanding and generation
  • Excellent at "who did X at time T" queries
  • No frame sampling strategy needed — model handles it
  • Best benchmark scores on EgoSchema, NExT-QA
  • Supports video upload or YouTube URL directly

✗ Limitations

  • Requires Google Cloud API key + cost per call
  • Not local/offline — data leaves the device
  • Cannot run on local GPU/MPS
  • Latency for long video analysis (2–10s per query)
GPT-4o (Video Frames)
OpenAI · 2024
API-only
API Required Frame-based

GPT-4o takes video as a sequence of sampled frames (not a video file directly). Each frame is sent as an image with timestamp metadata. Powerful reasoning but limited by frame budget (typically 20–50 frames per call).

✔ Strengths

  • Excellent natural language reasoning about scenes
  • Can narrate "person placed key on table at frame 420"
  • Familiar API, easy integration

✗ Limitations

  • No native video input — requires manual frame extraction
  • Frame budget limits long-video coverage
  • Expensive at scale (many frames = many tokens)
  • Less precise timestamps than Gemini's native video mode
LLaVA-Video (ByteDance)
ByteDance Research · 2024
7B / 72B
Video QA Open Source

LLaVA-Video is a 2024 open-source video LMM specifically designed for dense video understanding. Uses a "slow-fast" dual-encoder: slow path for key frames, fast path for motion context. 72B version competes with Gemini on short-to-medium videos.

✔ Strengths

  • Open source, runs locally
  • Strong on EgoSchema (egocentric action understanding)
  • Slow-fast architecture handles both key moments and continuity
  • 72B version near Gemini on several benchmarks

✗ Limitations

  • 7B version weaker than Qwen2.5-VL-7B on temporal reasoning
  • 72B requires >40 GB VRAM (not practical on local Mac)
  • Less polished timestamp output format
  • Separate HuggingFace integration needed
TimeSformer / VideoMAEv2 + LLM
Facebook AI / Shanghai AI Lab
85M–632M (encoder only)
Action Recognition Encoder-only

Pure video encoders pre-trained for action recognition (Kinetics-400/700). Cannot answer natural language queries on their own — require a separate LLM head. Good for the "detect action" part of Approach B pipeline.

✔ Strengths

  • Very accurate action labels (put in pocket, pick up, etc.)
  • Efficient — runs on CPU/MPS for short clips
  • Lightweight compared to LMMs

✗ Limitations

  • No natural language output — classification labels only
  • Cannot answer "where is the key" — only "action: pick up object"
  • Requires full pipeline: tracker + action head + LLM narrator
  • Much more complex to build and maintain
Grounding DINO + SAM 2 (Video Tracking)
IDEA Research / Meta · 2024
195M + 80M
Object Tracking Frame-level Precision

SAM 2 extends Segment Anything to video, providing pixel-precise tracking of any object across frames once identified. Combined with Grounding DINO for open-vocabulary detection, this gives frame-by-frame "where is the key" — but no temporal narration.

✔ Strengths

  • SAM 2: pixel-level object tracking across entire video
  • Grounding DINO: open-vocabulary detection (text → box)
  • Excellent for "show me where the key is in every frame"
  • Complementary to Phase 1 (Florence-2 / OWLv2)
  • Lightweight, runs on MPS

✗ Limitations

  • No LLM reasoning — cannot answer "who put the key in their pocket"
  • Needs a separate LLM to narrate results with timestamps
  • Best used as a tracker backbone within a pipeline
  • High memory for long videos (all frames stored)

5. Recommendation for Phase 2

★ Primary Recommendation: Qwen2.5-VL-7B in Video Mode + SAM 2 (optional precision layer)

Why Qwen2.5-VL is the Best Fit

The model is already installed and tested in Phase 1. Its video mode is a natural extension of the same AutoModelForImageTextToText pipeline with one architectural difference: instead of a single PIL image, the processor accepts a list of frames (or a video file) with per-frame timestamps. The model then produces answers that naturally reference time ("At second 663, the person placed the key in their coat pocket").

Qwen2.5-VL uses a dynamic Visual Tokens mechanism: it samples frames at configurable fps, assigns each frame a <|vision_start|> temporal tag, and its decoder can reference those tags when generating text. This is the same mechanism that Phase 1 already uses for spatial bounding box grounding — just extended to the time dimension.

How Timestamps Are Produced

Qwen2.5-VL accepts a video_start / video_end parameter per frame. You pass frames as:

{"type": "video", "video": frames_list, "fps": 1.0}

The model then answers with explicit second-level references. For an 11-minute video at 1 fps, you have 660 frames — well within the model's token budget at float16 on 16 GB unified RAM when chunked into 3-minute windows.

Long Video Strategy — Sliding Window

For a 30+ minute video: chunk into overlapping 3-minute windows (180 frames at 1 fps) with 30-second overlap. Run each window, collect all event mentions, then ask a final "summarisation" pass: "Given these events: [list], where was the key last seen before being moved?"

New Dependencies Required

  • sam2 (Meta, pip installable) — only if Layer 2 tracking is needed
  • decord or av — efficient video frame reading (faster than cv2 for long videos)
  • No new LLM weights needed — Qwen2.5-VL-7B already downloaded
Note on Apple Silicon (MPS): Qwen2.5-VL video mode works on MPS with the same float16 + use_cache=False + attn_implementation="eager" settings already used in Phase 1. For a 10-minute video at 1 fps (600 frames), expect ~45–90 seconds inference time on M1/M2 Max with 16 GB unified memory.

7. When to Use Gemini Instead

If the video exceeds 30 minutes, or if accuracy of the exact timestamp is business-critical (e.g., evidence-grade), use Gemini 2.0 Flash via API. It handles the entire video in one pass without chunking and produces sub-second timestamp precision. The integration is a simple REST call replacing the local model inference.
